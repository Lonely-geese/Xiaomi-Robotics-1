# RECAP 真机 rollout 数采

本目录整理自 192.168.32.160 的实际数采部署，采集模型为 RECAP epoch10 / step15490。控制入口来自该机正在运行的 `backups/before_strict_morning_restore_20261112_225111/run_robot.py`，录制、人工接管和标注后归位使用当前主目录中的模块。文件原始位置与 SHA-256 见 [来源记录](provenance/source_files.json)。

## 目录与数据流

```text
rollout/
  server/           小米原生推理服务、模型实现、TCP 客户端与环境版本
  control/          协议适配、VR 控制、人工接管、录制与检查工具
  runtime/          控制执行器、位姿转换、软停确认、VR 输入
  config/           固定模型身份、复位配置与环境配置示例
  scripts/          三个启动入口、模型校验、端口等待
  systemd/          用户服务，异常退出后等待 5 秒重启
  provenance/       32.160 源文件校验记录
```

```text
RECAP 原生服务 127.0.0.1:10090
        ↓
笛卡尔协议适配服务 127.0.0.1:10094
        ↓
VR 控制与数采 → robot HAL 127.0.0.1:7860 → 机器人
        ↓
LeRobot v2.1 数据目录、三路视频、状态、动作与人工介入信息
```

部署操作见 [使用说明](docs/usage.md)，数据字段及标注约定见 [数据说明](docs/data.md)。

控制端启动后会接管并复位双臂、打开双夹爪，再等待 Y 开始采集。应在现场确认复位路径安全后启动。异常自动重启同样会重新进入这套启动流程。

模型通过头相机全图、左腕全图及左腕中心 256×256 裁剪进行推理。录制保存头相机、左腕和物理右腕三个原始视角。模型动作只控制左臂，动作空间转换、速度检查、软停和控制权检查沿用现场实现。

本分支以 `recap` 为基础新增此目录。离线检查可使用 `python rollout/scripts/check_package.py --code-only`。真机启动需要外部模型包、CUDA 推理环境和已安装的 DeepTouch HAL/Quest 运行时。训练权重与处理器文件按使用说明配置到模型包路径。
